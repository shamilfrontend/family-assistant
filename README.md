# Семейный ассистент

Веб-приложение для одной семьи (родители + дети). Общее пространство с календарём, делами, покупками, документами и здоровьем — плюс AI, который отвечает и действует по этим данным.

Это не чат ради чата и не набор разрозненных списков. Данные семьи — источник правды; интерфейсы модулей и ассистент работают с одним и тем же состоянием.

## Зачем и для кого

Семья держит расписание, списки, сроки документов и медицинские факты в переписке, заметках и головах. Из-за этого легко пропустить кружок, истечение паспорта или прививку, а второй взрослый не видит полной картины.

Продукт для семьи, которая живёт вместе и ведёт быт, детей, документы и здоровье в одном месте. Типичные вопросы:

- «Что сегодня у нас?»
- «Когда истекает паспорт Маши?»
- «Какие прививки у Димы?»
- «Добавь молоко в список»
- «Кто забирает ребёнка в четверг?» — ответ из календаря: событие типа «забрать» с участниками на этот день.

## Принципы

1. **Одно пространство.** Одна семья — один набор данных. Нет отдельных «аккаунтов-островов» внутри семьи. До фазы 3 у человека только одна семья: второе приглашение — отказ.
2. **Данные семьи — источник правды.** Календарь, дела, покупки, документы и здоровье хранятся явно. AI не заменяет модули, а читает и изменяет их.
3. **AI действует только с подтверждением.** Вопросы можно отвечать сразу. Запись в данные — только кнопкой по id черновика в том же чате. Текст «да» черновик не применяет.
4. **Роли ограничивают видимость.** Ребёнок не видит чужие документы, чужое здоровье и настройки семьи. Свои документы и своё здоровье — только чтение. Сервер режет выборку до модели: роль нельзя обойти промптом.
5. **Одно место для факта.** Аллергии и особенности живут в профиле, не дублируются в здоровье. Напоминание в MVP — индикатор в интерфейсе, не письмо и не push. Без внешних каналов MVP не закрывает «пропустили, потому что не открыли приложение».

## Роли

| Действие | Взрослый | Ребёнок |
| --- | --- | --- |
| Настройки семьи, приглашения, роли | да | нет |
| Профили членов семьи | читать и менять | свой профиль — читать |
| Календарь | все: создавать, менять, удалять | свои ближайшие (участник) — только читать; не создаёт |
| Дела | все: создавать, менять, удалять, снимать «сделано» | свои: смотреть и отмечать выполнение; не создаёт и не удаляет |
| Покупки (общий список) | полный доступ, в том числе снять «куплено», удаление и очистка купленного | смотреть, добавлять, отмечать «куплено» на любую позицию; править свою до «куплено»; снять «куплено» нельзя; чужое не удаляет |
| Документы | все: создавать и менять | свои — только читать; чужие — нет |
| Здоровье | все: создавать и менять | своё — только читать; чужое — нет |
| Бюджет | читать и менять | нет |
| AI-чат | по всем данным семьи в рамках роли; видит чаты детей семьи | только в рамках своей роли; свой чат; чаты взрослых не видит |

Карточка без аккаунта (малыш) в данных есть, входа и чата нет. Чат появляется только у члена с аккаунтом.

## Семья, аккаунты, приглашения

Семью создаёт пользователь 18+. Возраст — самодекларация при регистрации, без проверки документов. Создатель указывает **имя и дату рождения** своей карточки, становится взрослым. Число взрослых не ограничено — «второй взрослый» в сценарии типичный, не лимит.

**Профиль и вход — разные вещи.** Взрослый заводит карточку члена семьи (имя, роль, дата рождения) без обязательного логина: так живут малыши. Приглашение привязывает аккаунт к выбранной карточке или создаёт новую — выбор взрослого в момент выдачи.

- Вход второго взрослого и детей, которым нужен свой доступ, — по одноразовой ссылке или коду от взрослого.
- Приглашение указывает роль, живёт 48 часов, его можно отозвать до использования. Код/ссылка одноразовые.
- Нельзя снять роль или удалить последнего взрослого. Уйти из семьи последний взрослый может только вместе с удалением семьи. Удаление семьи — подтверждение списком того, что сотрётся.
- Роль «взрослый → ребёнок» допустима, если остаётся хотя бы один взрослый.
- Пока нет фазы 3, живой аккаунт состоит только в одной семье. Приглашение в другую — отказ. После удаления входа email свободен: повторная регистрация создаёт новую семью; вернуться в старую — только новым приглашением.

Профиль члена семьи: имя, роль, дата рождения, контакты (телефон и/или email, необязательно), **аллергии и особенности** — единственное место этих фактов; ими пользуются экран здоровья и AI. Контакты не обязательны для карточки без входа; аккаунту для приглашения нужен канал доставки кода (ссылка показывается взрослому, он передаёт её сам).

## Сущности

Поля — минимум для MVP. Часовой пояс один на семью, без конвертации. Время в интерфейсе — пояс семьи, не устройства.

- **Семья** — пространство людей и данных; часовой пояс.
- **Член семьи** — карточка с профилем; аккаунт может быть не привязан.
- **Событие** — запись в календаре. Тип: школа, кружок, работа, день рождения, врач, забрать, другое. Дата и время или весь день; длительность необязательна; участники из семьи (минимум один); повтор: нет / еженедельно / ежегодно; дата конца серии необязательна; флаг «напомнить в интерфейсе». В MVP нет исключения одного вхождения. Правка: «только это» (копия отдельным событием) или вся серия. День рождения — отдельное ежегодное событие, не создаётся автоматически из даты рождения.
- **Дело** — название, исполнитель (член семьи, обязателен), срок, статус (открыто / сделано), повтор: нет / ежедневно / еженедельно. Отметка «сделано» у повтора закрывает текущее вхождение и открывает следующее: исходный срок + период, даже если закрыли позже.
- **Покупка** — название, категория из списка (продукты, быт, аптека, другое; по умолчанию «другое»), количество необязательно (без единиц измерения в MVP), отметка «куплено», кто добавил.
- **Документ** — владелец (член семьи), тип (паспорт, загран, полис, права, свидетельство, другое), номер необязателен, дата окончания. Несколько документов одного типа на человека допустимы. За 30 дней до окончания в интерфейсе статус «скоро истекает».
- **Мед. запись** — привязана к человеку, без дубля аллергий. Типы: врач (имя, специальность, телефон); прививка (название, дата); осмотр (тип, дата, заметка); приём (врач или название, дата/время → событие в календаре).
- **Категория бюджета** — имя и порядок в семье. При создании семьи: Продукты, Быт, Аптека, Транспорт, Другое; взрослые добавляют, переименовывают и удаляют (занятую расходами нельзя).
- **Расход** — название, сумма в рублях, категория, кто потратил (карточка семьи), дата. Ребёнок не видит.

## Состав MVP

Семь модулей сразу — слишком широко. Фаза 1 идёт пятью подфазами по порядку. Бывшие срезы: **A1 = 1.1–1.3**, **A2 = 1.4**, **B = 1.5**.

| Подфаза | Что входит | Готово когда |
| --- | --- | --- |
| **1.1** Каркас и семья | Docker, PostgreSQL, Prisma, Express, Vue 3, Caddy; регистрация, сессия `sid`, карточки, приглашения, роли, удаление аккаунта и семьи; тесты RBAC | Взрослый заводит семью и приглашает второго взрослого и ребёнка; ребёнок не проходит в `/family`; последний взрослый не удаляется |
| **1.2** Календарь | События, типы, повтор, правка «это / вся серия», фильтр по члену; экран «Сегодня» (события и «скоро») | Кружок еженедельно и день рождения ежегодно видны; ребёнок видит только свои ближайшие вхождения |
| **1.3** Покупки и AI | Общий список покупок; чат DeepSeek; Facts по календарю и покупкам; tool только покупка | Проверки манифеста 1–3. Вопросы про дела, документы и здоровье — «ещё не подключено» |
| **1.4** Дела и документы | Дела; документы с маской номера; AI: запись события и дела, отметки «сделано» / «куплено» | Проверка 4. Ребёнок не применяет create event/task |
| **1.5** Здоровье | Врачи, прививки, осмотры, приёмы; AI читает здоровье, писать мед. записи из чата нельзя | Проверка 5. Фаза 1 закрыта |

Порядок жёсткий: 1.2 не без 1.1, 1.3 не без 1.2, и так далее. **1.5 не начинается**, пока нет удаления семьи (1.1), маскирования номеров (1.4) и серверного RBAC (1.1). `Chat` в БД создаётся вместе с User в 1.1; экран чата и DeepSeek — в 1.3.

Ниже — модули полного MVP. Когда какой появляется — в таблице подфаз.

### 1. Семья и доступ (подфаза 1.1)

Регистрация 18+ (имя, дата рождения, email, пароль, пояс семьи), создание семьи, карточки членов, приглашения, роли, профили — по правилам выше. Сессия — httpOnly-cookie, не JWT в localStorage.

### 2. Календарь (подфаза 1.2)

Общие события с полями сущности. Просмотр всех или фильтр по человеку. Повтор нужен: кружки и школа — еженедельно, дни рождения — ежегодно.

Приём из модуля здоровья (подфаза 1.5) появляется в календаре как отдельный тип только для чтения. Источник — мед. запись: правка или удаление приёма обновляет или снимает событие. Из календаря приём как мед. факт не редактируется. Событие типа «врач», созданное в календаре, — обычное событие, не мед. запись; в интерфейсе подписано, что это не мед. карта. AI про приёмы читает только мед. записи, не события типа «врач». Тип `HEALTH_APPOINTMENT` в API до 1.5 не создаётся.

Напоминание в MVP — флаг и список «сегодня / скоро» в интерфейсе. «Скоро» для событий с флагом — сегодня и ближайшие 7 дней. Письма, push и Telegram — фаза 2.

### 3. Дела (подфаза 1.4)

Задача с названием, исполнителем, сроком, статусом и повтором. Взрослый видит все дела семьи. Ребёнок видит «мои дела» и отмечает выполнение; снять отметку может взрослый.

### 4. Покупки (подфаза 1.3)

Один общий список на семью. Быстрое добавление с телефона (только название) или через AI. Купленное взрослый может скрыть, снять отметку или очистить. Ребёнок работает с тем же списком: добавляет, отмечает любую позицию «куплено», правит свою до покупки.

### 5. Документы (подфаза 1.4)

Карточки на человека: тип, номер (необязательно), дата окончания, индикатор «скоро истекает» за 30 дней. В MVP — реквизиты и сроки, без обязательных сканов.

Полный номер виден только взрослому на экране документа. В списках, в ответах AI и в логах — маска вида `••••1234` (последние 4 символа). В промпт модели номер не передаётся: только тип, владелец, дата окончания и статус. В логах промптов, query-логах и ошибках полной строкой не хранится.

### 6. Здоровье (подфаза 1.5)

На каждого члена семьи: врачи, прививки, осмотры, приёмы. Аллергии и особенности не копируются сюда — они в профиле. Приём создаёт событие в календаре (синк в одну сторону, см. календарь). Ребёнок читает только своё здоровье. Подфаза 1.5 не начинается, пока нет удаления семьи, маскирования номеров и серверного RBAC.

### 7. AI-чат (подфаза 1.3)

Чат привязан к аккаунту, не к карточке без входа. Чаты взрослых не видны другим членам семьи и не заменяют переписку. Чаты детей семьи видны взрослым этой семьи.

Ассистент работает только по данным семьи и только в рамках роли. Выборка в контекст — по роли на сервере, не вся база. Умеет:

- ответить, что сегодня и на неделе (с 1.3);
- показать список покупок (с 1.3) и — с 1.4 — открытые дела;
- с 1.4 сказать сроки документов (номер в модель не уходит) и — с 1.5 — какие прививки и осмотры у человека;
- с фазы 2 сказать расходы и «кто сколько» за месяц (только взрослому);
- предложить создать или обновить запись в рамках текущей подфазы и применить черновик кнопкой да/нет с id черновика: в 1.3 — покупка; в 1.4 — событие, дело, отметка «сделано» / «куплено»; в фазе 2 — расход. Ребёнок применяет только покупку, «куплено» и «сделано» по своему делу — не событие, не новое дело и не расход.

Составной запрос («молоко и хлеб») дробится на отдельные черновики. Один черновик — одна операция. Если совпадений по имени 0 — сказать; если больше одного — уточнить списком карточек. Сопоставление по имени из профиля, без догадок.

Не умеет в MVP: искать «весь интернет» как основную фичу; менять данные без подтверждения кнопкой; обходить роли; удалять записи; создавать документы и мед. записи (это только экраны модулей); писать в чужой чат.

Язык ответов — язык сообщения пользователя, по умолчанию русский. Если LLM недоступна — короткий шаблон «ассистент сейчас не отвечает», без записи в данные.

Провайдер — **DeepSeek API**. Вызов только с бэкенда: ключ не уходит на клиент. Формат — Chat Completions, совместимый с OpenAI SDK (`base_url`: `https://api.deepseek.com`). Запись в данные — серверные tool-вызовы с проверкой роли, не свободный текст модели в БД.

## Что умеет и чего не умеет AI

**Умеет:** читать календарь, покупки и (с 1.4) дела и документы и (с 1.5) здоровье в рамках роли и (с фазы 2) бюджет — только взрослый; короткие ответы на бытовые вопросы семьи; черновик записи в рамках текущей подфазы и применение после подтверждения кнопкой.

**Не умеет:** быть мессенджером; ставить диагнозы и давать назначения; хранить секреты в обход ролей; действовать без подтверждения кнопкой; создавать из чата документы и мед. записи; применять черновик по тексту «да».

## Данные и удаление

В продукте есть ПДн, в том числе детей, номера документов и сведения о здоровье. Создатель семьи — 18+. Ребёнок получает вход и чат только по приглашению взрослого. Юридические тексты согласий — отдельный артефакт; в продукте до подфазы 1.5 нужны: серверный RBAC, удаление семьи, маскирование номеров, просмотр чата ребёнка взрослым.

Удаление аккаунта убирает вход (все сессии и чат); карточка члена остаётся, email свободен. Последний взрослый так уйти не может — только вместе с удалением семьи. Удаление карточки стирает профиль и связанные записи; если к ней был привязан аккаунт, он тоже удаляется. Удаление семьи стирает людей, события, дела, покупки, документы, мед. записи, расходы и истории чатов этой семьи — после подтверждения списком.

Отдельная юридическая политика и тексты согласий — не часть этого ТЗ, но продукт без удаления семьи, без маскирования номеров документов и без серверного RBAC не считается готовым к MVP.

## Вне скоупа

Чтобы не расползтись в первой версии:

- отдельные аккаунты для бабушек/дедушек и «расширенной семьи»;
- соцсеть, лента, комментарии;
- замена Telegram/WhatsApp;
- «семейный офис» на десятки модулей сразу;
- голос, Google Calendar и прочие внешние календари;
- бюджет, меню, сканы документов, школьная папка — это фаза 2, не MVP;
- внешние каналы напоминаний (email / push / Telegram) — фаза 2;
- исключения одного вхождения серии, единицы измерения в покупках;
- восстановление пароля (забыл пароль — не MVP).

## Дорожная карта

### Фаза 1 — MVP

Пять подфаз по порядку (бывшие срезы: A1 = 1.1–1.3, A2 = 1.4, B = 1.5):

1. **1.1 Каркас и семья** — стек, регистрация, карточки, приглашения, роли, удаление, RBAC. Навигация: «Сегодня»-заглушка и «Ещё» → семья. Календарь, покупки и чат в меню ещё нет.
2. **1.2 Календарь** — события, повторы, напоминания только в интерфейсе. `GET /reminders`: `today.tasks` и `soon.documents` пока `[]`.
3. **1.3 Покупки и AI** — общий список, быстрое добавление, чат DeepSeek: ответы по календарю и покупкам + черновик покупки. Первая поставка продукта.
4. **1.4 Дела и документы** — дела, документы с маской; AI: запись события и дела, отметки «сделано» / «куплено».
5. **1.5 Здоровье** — врачи, прививки, осмотры, приёмы; AI читает эти данные, писать мед. записи из чата нельзя.

Дальше — фаза 2 без перестановки этих пяти шагов.

### Фаза 2

- Планирование еды / меню на неделю и автодобавление продуктов в покупки.
- Семейный бюджет: расходы, категории, «кто сколько» за месяц (ребёнок не видит). Доходов и лимитов нет.
- Файлы к документам (сканы), папка «школа» (домашка, объявления).
- Уведомления: Telegram.

### Фаза 3

- Голосовой ввод.
- Интеграция с Google Calendar.
- Геймификация дел для детей.

## Как проверить

Пять вопросов из манифеста должны закрываться данными, не «памятью чата».

Подфаза 1.3:

1. «Что сегодня у нас?» — события календаря на сегодня, с фильтром по человеку.
2. «Добавь молоко в список» — черновик покупки в чате, запись только по кнопке; позиция видна в общем списке.
3. «Кто забирает ребёнка в четверг?» — событие типа «забрать» на этот день и его участники.

Подфаза 1.4:

4. «Когда истекает паспорт Маши?» — карточка документа, дата и статус «скоро истекает»; в ответе AI номер замаскирован или не показан. Если Маш несколько — уточнение списком, не первый попавшийся.

Подфаза 1.5:

5. «Какие прививки у Димы?» — мед. записи; до 1.5 допустим ответ «здоровье ещё не подключено».
